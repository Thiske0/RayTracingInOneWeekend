# Rust + CUDA raytracer

Photorealistic renderer written in Rust + CUDA.
The Rust + CUDA ecosystem allows for easy degugging because the same code can run on both CPU and GPU.

## Implementations

Each pixel corresponds to a single CUDA thread.
For each pixel rays are send out that bounce around in the scene to determine what color the pixel should get.
For opitmal performance when using multiple gpu's, the y-coorditates are interleaved.
To avoid communication, a single frame is limited to a single node, but multiple frames can be rendered on multiple nodes as they are fully independent.


## Repository Layout

```text
.
├── crates/
│   ├── gpu_builder/           # Create responsible for easy copying of complex objects between CPU and GPU
│   │   ├── macros/            # Procedual macros used to generate the code from copying data around
│   │   └── src/               # Wrappers around the code generated by the macro's
│   ├── gpu_builder_test/      # Tests for the gpu_builder crate
│   ├── grid_nd/               # multidimensional array with support for GPU
│   └── ref_builder/           # Support for references on the GPU (like unowned references and slices)
├── data                       # Data used by the renderer, for example the .obj file of the dragon
├── kernels                    # The code that will run on the GPU (also works on CPU)
│   └── lib.rs                 # Entry point
├── logs/                      # Job logs
├── lib/                       # Bundled Catch2 and MIPP dependencies
├── src/
│   ├── bin/
│   │   └── render.rs          # Application entry point
│   └── raytracer/             # Wrapper around the GPU kernels
└── make-video.sh              # sbatch script used to make the video
```

## Build

The build happens during the job to ensure the program is compiled for the correct GPU.
When getting getting network errors during compilation, please try to build on a login node to download the required crates.
This can be done using the following commands:
```bash
source ../load_env.sh
cargo build --release
```
Note: It is expected for this command to fail on login nodes since no GPU is present there, the important part is that the crates are now downloaded.

## Run

You can submit the job to create the video on leonardo by running this command:
```bash
sbatch make-video.sh
```

Feel free to make the following changes:
- change the amount of nodes by updating `#SBATCH --nodes=60` in `make-video.sh`.
- change the version of the drqgon rendered `perf_test(&mut options.render, DragonVersion::Blue)` line 762 in `src/bin/render.rs` (Options are `Blue`, `Glass`, `Gold`)
- change the time limit by updating `#SBATCH --time=00:15:00` in `make-video.sh`. (You can estimate the time needed using the existing results in `logs/`)
